เวอร์ชัน: v1.11.0
วันที่: 2026-08-19 18:51 น. (เวลาไทย)
สรุป: backtest ด้วยข้อมูลทางการ 6.6 ปี — ยืนยัน config ปัจจุบัน และพบว่า pivot ที่ดีที่สุดเปลี่ยนตามยุคตลาด
เทียบกับ: v1.10.0

==================================================================
รายละเอียดการเปลี่ยนแปลง
==================================================================

ผู้ใช้เสนอให้ใช้ข้อมูลจาก data.binance.vision ซึ่งเป็นคลังทางการของ Binance
เก็บเป็น ZIP รายเดือนตั้งแต่ปี 2020 ลึกกว่า REST API มาก

เพิ่มเครื่องมือ:
  fetch_binance_vision.py [ใหม่] ดาวน์โหลด+ตรวจ checksum+รวมไฟล์รายเดือน
                          จัดการไฟล์ที่มี/ไม่มีหัวตาราง และหน่วยเวลา ms vs
                          microseconds ที่ Binance เปลี่ยนกลางทาง
  backtest_full.py --data-dir  อ่านข้อมูลชุดนี้ (resample 4H จาก 1H)
  backtest_full.py --profile   ทดสอบโปรไฟล์จริงจาก config.yaml โดยตรง
                               กันพิมพ์ค่าเองผิดแล้วทดสอบคนละอย่างกับที่รันจริง

ข้อมูลที่ใช้: 15 เหรียญ x 6.6 ปี (2020-01 ถึง 2026-07) รวม ~830,000 แท่ง 1H
ครอบคลุมกระทิง 2021, หมี 2022, ฟื้นตัว 2023-2026

ผลของ config ที่รันอยู่จริง (สองโปรไฟล์รวมกัน):
    in-sample  (2020-2024)   1,154 ไม้  win 31.9%  +0.434R  PF 1.56
    out-sample (2024-2026)     551 ไม้  win 35.6%  +0.473R  PF 1.63
    รวม 6.6 ปี               1,707 ไม้  win 33.0%  +0.447R  PF 1.58
in-sample กับ out-of-sample ใกล้กันมาก = edge จริง ไม่ใช่ overfitting

การค้นพบที่สำคัญที่สุด — pivot ที่ดีที่สุดเปลี่ยนตามยุคตลาด:
    pivot      2020-2024     2024-2026
      3         +0.522R       +0.420R
     15         +0.271R       +0.572R
  swing เล็กชนะช่วงแรก swing ใหญ่ชนะช่วงหลัง ไม่มีค่าตายตัวที่ดีเสมอ
  แต่ละโปรไฟล์เดี่ยวๆ แกว่งแรง (0.522->0.420 และ 0.187->0.693)
  พอรวมกันกลับนิ่ง (0.434->0.473) = การกระจายความเสี่ยงข้ามขนาด swing
  ดีกว่าการจูนหาค่าเดียว

  ดังนั้นการรันสองโปรไฟล์ตามที่ผู้ใช้ขอใน v1.10.0 ถูกต้องเชิงสถิติด้วย
  ไม่ใช่แค่เรื่องความชอบ — จึงไม่เปลี่ยน config ใดๆ ในเวอร์ชันนี้

แก้ข้อสรุปที่เคยรายงานผิดไป 2 เรื่อง (ทั้งคู่เกิดจากข้อมูลครอบคลุมช่วงตลาดแคบไป):
  1. v1.9.0 สรุปว่า pivot 3->15 ดีขึ้น — จริงเฉพาะยุค 2024-2026 เท่านั้น
     ไม่ใช่คุณสมบัติถาวร (แต่ v1.10.0 แก้ปัญหานี้ไปแล้วโดยรันทั้งสองแบบ)
  2. v1.7.0 สรุปว่า HTF filter ทำให้แย่ลงทุกตัวชี้วัด — บนข้อมูล 6.6 ปี
     กลับเป็นกลางๆ (short: 0.488 -> 0.506 ดีขึ้นเล็กน้อยด้วยซ้ำ)
     ยังปิดไว้เหมือนเดิมเพราะตัดสัญญาณทิ้ง 40% โดยไม่ได้อะไรกลับมา
     แต่คำว่า 'ตัวถ่วง' ที่เคยใช้นั้นแรงเกินจริง

สิ่งที่ยืนยันได้แน่นอนบนข้อมูลลึก: ตัวกรอง divergence ได้ผลจริง
  6,130 ไม้ (+0.34R) -> 1,296 ไม้ (+0.488R)
