เวอร์ชัน: v1.15.0
วันที่: 2026-08-19 23:32 น. (เวลาไทย)
สรุป: ลดสรุปรายวันเหลือสัปดาห์ละครั้งอัตโนมัติเมื่อโควตา LINE เกิน 50%
เทียบกับ: v1.14.0

==================================================================
รายละเอียดการเปลี่ยนแปลง
==================================================================

ผู้ใช้ถามว่าสรุปรายวันจะกินโควตาฟรีของ LINE ไหม จึงวัดจริงก่อน:

  โควตาบัญชี (อ่านจาก LINE API จริง)  300 ข้อความ/เดือน  ผู้ติดตาม 1 คน
  วัดสัญญาณจริงด้วย config ปัจจุบัน บน universe เต็ม 100 เหรียญ ย้อนหลัง 30 วัน:
      1h short  118 | 1h wide  39 | 4h  14  = 171 สัญญาณ/เดือน (5.7/วัน)
      แยกเกรด: A 33 | B 25 | C 113
  รวมกับสรุปรายวัน 30 = 201/300 = 67% ของโควตา -> ยังไม่เกิน แต่เหลือที่ว่าง 33%

ผู้ใช้จึงขอให้เช็คโควตาเป็นระยะ ถ้าเกิน 50% ให้ลดสรุปรายวันเหลือสัปดาห์ละครั้ง
(ต้นสัปดาห์ = วันจันทร์) เพื่อกันโควตาไว้ให้สัญญาณเทรดซึ่งสำคัญกว่า

สิ่งที่เพิ่ม:
  line_notifier.quota_status()  อ่านโควตาและยอดใช้งานจาก LINE API
                                คืน None ถ้าแผนไม่จำกัด หรือถ้าติดต่อ LINE ไม่ได้
  daily_report.should_send()    ตัดสินใจว่าจะส่งวันนี้ไหม
  config daily_report.quota_throttle  {enabled, threshold_pct: 50, weekly_day: 0}
  แถว 'โควตา LINE' ในสรุปทุกฉบับ (เหลือง >50%, แดง >80%)
  --force สำหรับสั่งส่งข้ามการจำกัด

กฎ (ตามที่ผู้ใช้กำหนด):
  ใช้ไป <= 50%  -> ส่งทุกวันตามปกติ
  ใช้ไป >  50%  -> ส่งเฉพาะวันจันทร์ และในข้อความจะอธิบายเหตุผลไว้ด้วย
                   ไม่ให้หายไปเงียบๆ จนผู้ใช้สงสัยว่าบอทพัง

จุดที่ปรับต่างจากที่ผู้ใช้บอกเล็กน้อย (แจ้งผู้ใช้แล้ว):
  ผู้ใช้บอกว่า 'เช็คทุกอาทิตย์' แต่ implement เป็นเช็คทุกครั้งที่จะส่ง (คือทุกวัน)
  เพราะถ้าเช็คสัปดาห์ละครั้ง โควตาอาจทะลุเกณฑ์ตั้งแต่วันอังคารแล้วยังส่งรายวัน
  ต่อไปอีก 6 วันกว่าจะรู้ตัว ส่วนการเช็คทุกครั้งไม่มีต้นทุนเพิ่ม (เรียก API 2 ครั้ง
  ซึ่งไม่นับโควตา) ตอบสนองทันที และไม่ต้องเก็บ state ไฟล์ที่อาจเพี้ยน
  อีกทั้งกลับมาส่งรายวันเองอัตโนมัติเมื่อ LINE รีเซ็ตตัวนับต้นเดือน
  กฎการตัดสินใจยังเป็นของผู้ใช้ทุกประการ (50% -> เฉพาะวันจันทร์)

การออกแบบเชิงป้องกัน:
  - เช็คโควตาก่อนดึงข้อมูลจาก exchange วันที่ข้ามจึงไม่เสียทรัพยากรเลย
  - ถ้าอ่านโควตาไม่ได้ (LINE ล่ม) จะส่งตามปกติ ไม่ใช่เงียบหาย
    เพราะระบบตรวจสอบล่มไม่ใช่เหตุผลที่จะหยุดส่งงานจริง

ทดสอบครบ 16 กรณี (โควตา 5/50/50.3/80/100% x จันทร์/พุธ/อาทิตย์ + กรณีอ่านไม่ได้)
ผลถูกต้องทั้งหมด ทดสอบกับ LINE API จริงและบน VM แล้ว timer ยังตั้งไว้ปกติ
